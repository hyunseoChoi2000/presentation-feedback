# 🎤 프로젝트 발표 리뷰 & 피드백

프로젝트 발표 후 받은 리뷰를 정리한 문서입니다. 다음 발표를 준비할 때 체크리스트로 활용합니다.

## 1. 규칙 준수
- **발표 시간, 제출 기한, 제출 조건과 형식을 반드시 지킨다.** 내용이 좋아도 규칙을 어기면 평가에서 손해를 본다.

## 2. 발표 태도와 전달력
- **대본을 그대로 읽지 않는다.** 대본만 보고 읽으면 청중의 집중을 끌어내기 어렵다.
- **무대를 넓게 활용한다.** 한 자리에만 서 있지 말고 자연스럽게 움직이며 발표한다.
- **유머와 흥미 요소를 더한다.** 적절한 재미 요소는 청중의 집중도를 높인다.

## 3. 청중 눈높이에 맞춘 설명
- **전문 용어는 풀네임을 함께 적고, 쉬운 말로 풀어서 설명한다.**
- **청중의 수준을 고려해 간단하게 설명한다.** 공감대를 형성하면 발표에 더 몰입시킬 수 있다.

## 4. 발표 자료 구성
- **슬라이드를 너무 빽빽하게 채우지 않는다.** 여백을 두고 핵심만 담는다.
- **코드는 흐름 위주로 설명한다.** 세부 조건 등 디테일한 설명은 발표에서 큰 의미가 없으므로 자료에서 줄인다.

## 5. 어필과 강조
- **강조할 부분을 의식적으로 설계한다.** 잘한 점은 자신 있게 드러내고 강조한다.
- **핵심 질문: "이 내용을 얼마나 효과적으로 어필할 수 있는가?"**

## 6. 청중으로서의 자세
- **듣는 사람의 태도도 평가 대상이다.** 다른 팀 발표에도 적극적으로 질문하며 참여한다.

---

## ✅ 발표 전 체크리스트
- [ ] 발표 시간 내에 끝나도록 리허설했는가?
- [ ] 제출 기한·조건·형식을 확인했는가?
- [ ] 대본 없이 핵심 내용을 말할 수 있는가?
- [ ] 전문 용어에 풀네임과 쉬운 설명을 붙였는가?
- [ ] 슬라이드가 과하게 빽빽하지 않은가?
- [ ] 코드 설명은 흐름 중심으로 정리했는가?
- [ ] 강조하고 싶은 성과가 분명히 드러나는가?
- [ ] 청중의 관심을 끌 요소(유머, 사례 등)를 준비했는가?
